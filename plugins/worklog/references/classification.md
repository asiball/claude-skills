# 再利用候補の分類基準

振り返りで見つけたものは、次のうち **ちょうど 1 つ** の置き場所に流す。

## 早見表

| 見つけたもの | 置き場所 |
|---|---|
| 一度きり・再利用の見込みが低い・既存情報で十分・記録コストの方が高い | 何もしない |
| 単純なコマンド、毎回同じ手順、AI の判断が不要 | script |
| エージェントが常時守るべきルール、触ってはいけない領域、必ず確認すべき事項 | AGENTS.md / CLAUDE.md |
| 人間にも必要な開発ルール（セットアップ、build、test、contributor 向け） | README.md / CONTRIBUTING.md |
| プロジェクト固有の知識、設計背景、仕様、トラブルシュート結果 | docs |
| 再利用可能な AI の判断手順・ワークフロー | Skill 候補 |

## 各置き場所の条件

### 何もしない

- 一度きりの情報
- 将来再利用する可能性が低い
- 既存情報で十分
- 記録するコストの方が高い

迷ったらここ。

### docs

- プロジェクト固有知識、設計上の背景、ハードウェア仕様、API 仕様
- トラブルシュート結果、アーキテクチャ上の判断
- 人間と AI の両方が後から参照すべき情報

### README.md / CONTRIBUTING.md

人間にも AI にも共通して有用な情報はこちらを優先する。

- セットアップ、build 方法、test 方法、開発方法、contributor 向けルール

既に README / CONTRIBUTING に正本がある場合、AGENTS.md 等へ同じ内容をコピーしない。

### AGENTS.md / CLAUDE.md

- エージェントが常時守るべきルール
- リポジトリ固有の重要な制約、編集してはいけない領域、必ず確認すべき事項
- エージェント固有の作業上のガードレール

README / CONTRIBUTING / docs と重複させず、可能な限り正本への参照にする。
手順が長くなってきたら、それは Skill の兆候（常時読み込む内容ではない）。

### script

- AI による判断が不要
- deterministic に処理できる
- 毎回同じコマンドを実行する
- shell / Python / Makefile 等で安全に自動化できる

例: format, build, test, lint, static analysis。これらを Skill にしない。

### Skill 候補

以下を **すべて** 満たすものだけ。

- AI による判断が必要
- 複数ステップからなる
- 同じ判断方法を繰り返し利用する（毎回同じ説明を AI にしている）
- 手順や評価基準に一定の安定性がある
- 一般的な既存 Skill では代替しにくい
- プロジェクトまたは組織固有の判断方法である
- 再利用することで明確な価値がある

Skill 候補は記録に留める。作成判断・置き場所・社内共有の基準は `${CLAUDE_PLUGIN_ROOT}/references/skill-lifecycle.md` にあり、再検出された候補は `/worklog:end` が `${CLAUDE_PLUGIN_ROOT}/references/skill-creation.md` の手順で作成する。
